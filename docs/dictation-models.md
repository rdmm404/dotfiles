# Local dictation ASR options (26 Oct 2026)

## Bottom line

For English push-to-talk, the best low-risk experiment is Voxtype's Parakeet `parakeet-tdt-0.6b-v3` (ONNX). It should be much lighter on the GPU than Whisper because it can run on CPU; the RTX 4070 Ti SUPER is not required. But no primary source establishes a same-machine accuracy or latency win over this user's `large-v3-turbo` + Vulkan/flash-attention setup. Test on the user's own mic and vocabulary before deciding. If preserving the GPU for games matters more than absolute recognition quality, a CPU Parakeet run is the leading tradeoff. If maximum accuracy/domain flexibility wins, keep Whisper turbo and enable `gpu_isolation` to release VRAM between recordings.

The daemon logs showed ~117 seconds transcribed in ~1.35 seconds, already about 87x real time; this is an observed service timing, not a controlled comparative benchmark. After enabling five-second eager chunks and paste output, a subsequent 10.5-second dictation finished its remaining transcription in 0.13 seconds and pasted about 0.26 seconds after recording stopped. The user reported an instantaneous experience. Keep those working settings unless accuracy issues emerge. Compare models on the same recordings, measuring release-to-text latency rather than inference alone.

## How to interpret the comparisons

- WER is benchmark-set dependent; it is not “dictation accuracy.” NVIDIA's Parakeet WERs are from its stated Open-ASR datasets and remove punctuation/capitalization errors. The V2/V3 figures are not a fair direct comparison with a personal Whisper transcription, and v3's multilingual coverage can matter even if English-only v2 edges the aggregate score.
- Voxtype's reported Parakeet, Moonshine, Whisper and Cohere speed numbers use different machines and often CPU-vs-GPU setups. They demonstrate feasibility, not a fair head-to-head on this 4070 Ti SUPER. The user's current result is already exceptional. A controlled comparison should use identical mic clips, warm-up, repeated trials, release-to-text wall time, and manual error counts for names, homophones, numbers, punctuation, and repeated words.
- For short push-to-talk, **eager processing is not the first optimization**: Voxtype describes Whisper eager mode as chunking audio while recording, mainly for slow machines/long passages; it trades some single-pass consistency for overlap of compute and recording. The current GPU path and short utterances are poor candidates. The setting is a Whisper option; don't mistake it for Parakeet streaming. [v1.1.1 config](https://github.com/peteonrails/voxtype/blob/v1.1.1/docs/CONFIGURATION.md)

## Practical recommendation / contention

1. If willing to compare another engine, try **Parakeet TDT v3 on CPU** first: it preserves punctuation/capitalization, saves GPU capacity, and the user's GPU is not needed for inference. Only try its CUDA execution provider if CPU latency is not enough; CUDA can contend with a game just as Whisper can.
2. If Whisper's accuracy is preferable, use `gpu_isolation=true` (or on-demand loading) so the large model doesn't reserve VRAM while idle. Isolation avoids persistent memory reservation, not inference-time GPU contention; CPU Parakeet avoids most ASR GPU work altogether.
3. Use Moonshine only if ultra-small footprint/short-utterance speed is the priority and its lowercase/unpunctuated output and accuracy pass a personal test. Avoid asserting Moonshine v2's latest streaming claims apply to Voxtype's experimental batch backend.
4. For a clean model-only test, compare three warm runs per same saved recording with no changes to mic/audio preprocessing or chunking. Record p50 latency and correction burden; report actual engine/backend/model. Separately compare the complete interactive workflows, including the current successful eager/paste configuration; do not disable that working configuration merely for a benchmark.
