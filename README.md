# Dotfiles

This repository uses `dot` to install applications and link shared and
platform-specific configuration on macOS, Omarchy, Ubuntu, and Debian.

The [Ubuntu SSH-first setup](docs/ubuntu-setup.md) keeps XFCE unchanged and
selects Zsh, CLI tools, and Herdr rather than desktop applications.
The [Debian agent-host setup](docs/debian-setup.md) uses the same shell foundation
without deploying Nautilus backup profiles or taking ownership of agent units.
It includes the separately enabled [Bebop home/system backup](docs/bebop-backup.md).

## Quick start

From a clone of the repository:

```bash
./dot doctor
./dot install
./dot deploy --dry-run --verbose
./dot deploy
```

For first-time setup, the combined command installs the selected applications
and then deploys configuration:

```bash
./dot bootstrap --dry-run --verbose
./dot bootstrap
```

Optional applications can be included with `--include optional`. Deployment
conflicts are reported; use `--replace` only when the existing paths should be
backed up and replaced. There are no routine confirmation prompts. See the
[current CLI specification](docs/dot-cli-spec.md) for deployment, import,
and backup workflows.

## Everyday use

```bash
./dot deploy                              # reconcile links; quiet when unchanged
./dot add ~/.config/my-tool --platform     # import a directory for this platform
./dot add ~/.some-config --global          # import a shared file
./dot deploy --replace                     # back up conflicts, then link repo versions
./dot backups list
./dot backups restore latest
```

`add` imports recursively and links files back into place. It never overwrites
tracked files or stages anything in Git. Preview changes with `--dry-run`.

## Omarchy calculator

**Super+Ctrl+Q** or **Calculator (Python)** in the app launcher opens a persistent
floating IPython calculator with SymPy and units. Closing the window keeps its
state; `exit()` starts fresh next time. See the [calculator guide](docs/python-calculator.md).

## Linux keyboard permissions

VIA/Vial need raw HID access on Linux. Rules live in `system/linux/udev/`,
separate from the home-directory layers: Keychron access is vendor-wide (`3434`),
while the AL80 rule matches only `28e9:30af` (its vendor ID is shared with other
GDMicro devices).

```bash
./dot udev --dry-run --verbose
./dot udev
./dot udev --replace            # back up and replace differing installed rules
```

This installs root-owned `0644` copies into `/etc/udev/rules.d/`, reloads udev,
and reapplies permissions to connected HID devices. Authentication uses `sudo`
in an interactive terminal, or `pkexec` otherwise. Unchanged rules need no
privileges. Differing rules require `--replace`; backups remain beside the
installed rules as `*.rules.bak.<timestamp>`. Non-regular destinations are refused.

The command skips macOS. It is deliberately separate from `deploy` and
`bootstrap`: those commands do not change system device permissions. After
installation, refresh VIA and authorize the keyboard again.

Run `bash tests/run` for the test suite (requires Python, Stow, ripgrep, and UV).

## Dependencies

- Bash 3.2 or newer
- Python 3.7 or newer, using only the standard library, for filesystem
  commands such as `doctor`, `deploy`, `add`, `undeploy`, and `backups`
- GNU Stow for deployment
- UV for opt-in TOML composition; its inline-dependency helper installs a pinned
  TOML library in an isolated environment (Python 3.9+ for that helper)

`dot install` installs Stow and UV from the core manifest. Install Python
separately if needed; `dot install` itself does not require Python.

## Shared configuration and platform overrides

The command detects the active platform. A platform file replaces a global file
at the same destination **entirely**. To merge instead, name the platform file
`config.merge.toml`; it overlays global `config.toml` and deploys as `config.toml`.
Tables merge recursively; other values, including arrays, are replaced.
If both platform names exist, the full file wins and deploy/doctor warn.

Herdr uses `global/.config/herdr/config.toml` as its canonical configuration and
`platforms/omarchy/.config/herdr/config.merge.toml` for desktop-only settings.
Ubuntu uses the global file directly. **prefix+a** opens the
[agent launcher](docs/herdr-launch.md).

Merged output lives under `${XDG_STATE_HOME:-~/.local/state}/dot/generated/`,
is symlinked to the normal application path, and is regenerated by `dot deploy`.
View it with `less ~/.config/herdr/config.toml`; edit the source files for lasting
changes. Edited generated output requires `--replace` and is backed up first.
See [composition details](docs/configuration-composition-proposal.md).
Automated filesystem tests use temporary homes and state directories.
